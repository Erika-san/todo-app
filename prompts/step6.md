# ステップ6: リスト・「今日」ビュー・絞り込み

CLAUDE.md と docs/spec.md(第2章 決めたこと、第3章 機能一覧、第5章 画面仕様、第7章 API仕様、第8章 業務ルール・バリデーション)を読んでから始めてください。

## 対象の機能
- F-10 リストの作成・名前変更・削除: サイドバーで操作。削除時、中のタスクはインボックスへ移る。
- F-11 絞り込み: 「すべて / 未完了 / 完了」の切り替え。
- F-12 「今日」ビュー: 期限が今日以前の未完了タスクを、全リスト横断で表示。
- あわせて「インボックス」(どのリストにも入っていないタスク)のビューも作る。

## API
- 仕様書 第7章の GET / POST /api/lists、PATCH / DELETE /api/lists/:id を作る。
  - GET は各リストの未完了数付き。
  - リスト名は必須・1〜30文字・同じユーザー内で重複不可(仕様書 第8章)。重複は「同じ名前のリストがあります」。
  - 色は自動で割り当て、名前変更時に変えられるようにするかは提案して確認をとる。
  - DELETE ではリストだけを消し、中のタスクは list_id が NULL(インボックス)になる(DB の ON DELETE SET NULL を利用)。
- GET /api/tasks に、仕様書どおり ?listId= / ?view=today / ?status=todo|done の絞り込みを足す。
  - 「今日」の判定は利用者の端末の日付で行う(仕様書 第8章 ルール5)。サーバーに日付を渡すか、画面側で絞るかは、どちらがよいか判断して報告する。
- PATCH /api/tasks/:id で listId も変えられるようにする。他人のリストの ID を指定されたら 404 にする。
- これまでと同じく、すべてログイン確認と user_id での絞り込みを通す。

## 画面
見た目は references/design/html/pc-main.html、sp-list.html、sp-menu.html(と png/ の同名画像)に合わせる。
- サイドバー: 「今日」「インボックス」(それぞれ未完了数)、リスト一覧(色・名前・未完了数)、「リストを追加」。今いるビューに印を付ける。
- リストの操作: 追加は名前を入れて Enter。名前変更と削除は、各リストのメニュー(…)から。削除時は「○件のタスクはインボックスへ移ります」と確認ダイアログを出す。
- 「今日」ビュー: 見出しに日付。お手本どおり「期限切れ」「今日」「完了」に分けて表示し、各行にリスト名を出す。進み具合(○件中○件完了)も表示する。
- 絞り込みタブ: 「すべて / 未完了 / 完了」と件数。
- 追加欄: 今開いているビューに合わせる(リストを開いていればそのリストに、「今日」なら期限を今日にして追加)。
- 詳細パネル: 「リスト」欄を足し、インボックスと各リストから選べるようにする。
- スマホ: サイドバーは ☰ ボタンで開くメニューにする(sp-menu.html)。
- 初期表示: ログイン後は「今日」ビューを開く。どのビューを開いているかは URL でわかるようにし、再読み込みや「戻る」でも同じビューに戻れるようにする。

## 確認
- Playwright で PC(1280幅)とスマホ(390幅)の両方で次を試し、スクショを screenshots/step6/ に保存する。
  - リストを作る → そのリストでタスクを追加 → サイドバーの件数が増える
  - リスト名の重複・空欄・31文字でエラー
  - リスト名を変える
  - タスクを詳細パネルで別のリストに移す
  - タスクの入ったリストを削除 → 確認ダイアログ → タスクがインボックスに残っている
  - 「今日」ビューに、期限切れと今日の未完了タスクが全リスト横断で出る。期限が明日のタスクや期限なしのタスクは出ない
  - 絞り込みタブの切り替えと件数
  - スマホで ☰ からメニューを開いてビューを切り替える
- テスト用ユーザー2人で、他人のリストへの PATCH / DELETE と、他人のリストへのタスクの移動が 404 になることを確認する。
- テストで作ったユーザーとデータは最後に削除する。
