# ステップ3: 認証(ログイン・新規登録・ログアウト)

CLAUDE.md と docs/spec.md(第5章 画面仕様、第8章 バリデーション)を読んでから始めてください。

## 前提
- Next.js 16 / @supabase/ssr を使う。この版での正しい書き方(ログイン状態の確認やリダイレクトを書く場所など)を、AGENTS.md の案内やインストール済みパッケージの説明で確かめてから書く。古い版の書き方を推測で使わない。
- 新規登録時の名前は、Supabase Auth の登録データとして渡す(ステップ2のトリガーがそれを users にコピーする)。
- 見た目は references/design/html/pc-login.html・pc-signup.html と、png/ の同名画像に合わせる。CSS はトークン(src/styles/tokens.css)を使う。

## やること
1. Supabase のクライアントを、サーバー用とブラウザ用に分けて用意する。
2. 画面を作る。
   - S-01 ログイン(/login)
   - S-02 新規登録(/signup)
   - 仮のタスク一覧(/tasks): 「ログイン中: 名前」とログアウトボタンだけを表示する。本物の一覧はステップ4で作る。
3. 動きを作る。
   - 新規登録が成功したら、自動でログインして /tasks へ移動する。
   - ログインが成功したら /tasks へ移動する。失敗したら「メールアドレスまたはパスワードが違います」と表示する。
   - ログアウトしたら /login へ戻る。
   - ログインしていない人が /tasks を開いたら /login へ戻す。
   - ログイン中の人が /login や /signup を開いたら /tasks へ移動する。
4. 入力チェックは仕様書 第8章のとおり(名前は必須・50文字まで、メール形式、パスワード8文字以上)。Zod のスキーマを1か所に書き、画面とサーバーの両方で使う。
5. サーバー側でログイン中のユーザーを確かめるときは、なりすましを防ぐ安全な方法を使う(Supabase が推奨する方法を確認して使うこと)。

## 先に提案して確認をとること
- Supabase は初期設定で「登録時に確認メールのリンクを押さないとログインできない」設定になっている。個人用アプリとしてこれをどうするか(オフにする / オンのまま確認メールの画面を作る)、長所・短所とおすすめを示して、私の確認を待つ。Supabase の管理画面で私が変える必要がある設定があれば、その手順も示す。

## 確認
- Playwright で、PC(1280幅)とスマホ(390幅)の両方で次を試し、スクショを screenshots/step3/ に保存する。
  - 新規登録 → /tasks に名前が出る → ログアウト → /login に戻る
  - 間違ったパスワードでログイン → エラー表示
  - 入力チェックのエラー表示(空欄、メール形式、短いパスワード)
  - 未ログインで /tasks を開く → /login に戻される
- テストで作ったユーザーは、最後に削除する(users の行も一緒に消えることを確認)。
