## 前半: アプリの仕上げ

### 点検すること
- 空のときの表示: すべてのビュー(今日、インボックス、各リスト、絞り込みの各タブ)で、0件のときの表示が出るか。
- エラー表示: 通信が切れたとき、保存に失敗したとき、入力ミスのときに、決まった日本語の文言が出るか。英語のエラーがそのまま出る所が残っていないか。
- スマホ表示: 375px〜1440px の幅で崩れないか(仕様書 第9章)。768px 未満でサイドバーがメニューにたたまれるか。押せる所は 44px 以上か。
- 読み込み中の表示: 通信が遅いときに、何も起きていないように見える所がないか。
- アクセシビリティ: キーボードだけで主な操作ができるか、ボタンに読み上げ用の名前があるか、文字のコントラストは 4.5:1 以上か。

### 受入テスト(仕様書 第9章)
- 別アカウントでログインし、最初のアカウントのタスク ID を URL や API に入れても 404 になること。
- リストを消しても、中のタスクがインボックスに残ること。
- そのほか、仕様書 第3章の Must 機能(F-01〜F-12)がすべて動くことを、PC(1280幅)とスマホ(390幅)で一通り確かめ、スクショを screenshots/step7/ に保存する。
- テストで作ったユーザーとデータは最後に削除する。

## 後半: ドキュメントの見直し(私の「後半に進んで」の合図のあとで)

直す前に「どこを、どう直すか」の一覧を出して、私の確認をとること。

### 少なくとも確認すること(これまでの作業で、仕様書とずれが出た所)
- 第6章 ERD: 図だけで文字の列一覧がなく、AI が読めなかった。実際の列(users.updated_at を含む)を表で書き足す。
- 第5章・第8章 文言: 実装で足した文言(「名前を入力してください」「メールアドレスを入力してください」「このメールアドレスはすでに登録されています」、通信制限時の案内、「保存できませんでした…」、確認ダイアログの「タスクを削除」など)を反映する。
- 第5章 画面: 「パスワードを忘れた方」のリンクは置かないこと、トップ(/)はログイン状態で /tasks か /login に振り分けること、詳細パネルの URL が /tasks/<ID> になることを書く。
- 第2章・第9章 技術: 実際のバージョン(Next.js 16、Prisma 7 とアダプター)、Middleware が proxy になったこと、DB とサーバー処理の場所がソウル(icn1)であることを書く。
- 第9章 セキュリティ: 「RLS で API のチェック漏れを DB 側で止める」と書いてあるが、Prisma は管理者として接続するため RLS は効かない。本当の守りは API の user_id での絞り込みで、RLS は Data API を通る接続に対する予備の守りだと正しく書き直す。
- 第9章 開発ステップ: GitHub・Vercel の接続はステップ4で行ったこと。Vercel では「GitHub につないだ後の push」でないとデプロイが始まらなかったこと。
- 運用: マイグレーションは手元で行い、DB を変えるときは「反映してから push」の順番にすること。Vercel の環境変数は3つで、DIRECT_URL は置かないこと。新規登録は開けたままにしていること。Supabase の無料プランは使わない期間が続くと一時停止されること。
- 第3章 機能一覧: Must(F-01〜F-12)がすべて完了したことがわかるようにする。
