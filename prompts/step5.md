# ステップ5: 編集と削除(詳細パネル・期限・優先度)

CLAUDE.md と docs/spec.md(第3章 機能一覧、第4章 ユーザーフロー、第5章 画面仕様、第7章 API仕様、第8章 業務ルール・バリデーション)を読んでから始めてください。

## 対象の機能
- F-06 タスク編集: タイトル、メモ(description)、期限、優先度を変更できる。
- F-07 タスク削除: 確認してから削除する。
- F-08 期限の設定: 日付を選ぶ。期限切れは赤字で表示する。
- F-09 優先度の設定: 高・中・低。高は一覧の行に印を付ける。

リスト(F-10)はステップ6で作る。このステップでは詳細パネルの「リスト」欄は置かないか、見た目だけにする。どうしたかを報告すること。

## API
- PATCH /api/tasks/:id を、status だけでなく title / description / dueDate / priority も一部更新できるようにする。
- DELETE /api/tasks/:id を作る。
- ステップ4と同じく、すべてログイン確認と user_id での絞り込みを通し、他人や存在しない ID は 404 にする。
- 入力チェックは仕様書 第8章どおり(タイトル必須・1〜100文字、メモ1,000文字まで、期限は日付形式で過去も可、優先度は high / medium / low)。Zod のスキーマは画面と API で共用する。

## 画面
- S-04 詳細パネル: 一覧の行を押すと開く。PC は右側のパネル、スマホ(768px 未満)は全画面。見た目は references/design/html/pc-main.html の右側と sp-detail.html に合わせる。
  - タイトル、完了チェック、期限(「今日」「明日」「なし」のボタン付き)、優先度(高・中・低の切り替え)、メモ(文字数表示付き)、削除ボタン、作成日。
  - 入力欄から離れたら自動で保存し、「保存しました」と小さく表示する(仕様書 第5章)。保存は楽観的更新、失敗したら元に戻してエラー表示。
  - ×(スマホでは戻る)で閉じる。Esc キーでも閉じる。
- 削除: 確認ダイアログ(「『○○』を削除します。元に戻せません。」)を出し、OK なら削除してパネルを閉じる。ブラウザの confirm() は使わず、画面の中にダイアログを作る。
- 一覧の行:
  - 期限を表示する(今日・明日・昨日は言葉で、それ以外は月/日)。
  - 期限切れ(未完了で、期限が今日より前)は赤字。完了したタスクは期限が過ぎていても赤くしない。
  - 優先度「高」は印を付ける(お手本では旗のアイコン)。
  - メモがあるタスクには印を付ける。
- 「今日」や「期限切れ」の判定は、利用者の端末の日付で行う(仕様書 第8章 ルール5)。サーバーの UTC で判定しない。

## 確認
- Playwright で PC(1280幅)とスマホ(390幅)の両方で次を試し、スクショを screenshots/step5/ に保存する。
  - 行を押して詳細を開く → タイトル・メモ・期限・優先度を変える → 閉じる → 一覧に反映され、再読み込みしても残っている
  - 期限を昨日にすると赤字、完了にすると赤字が消える
  - 入力エラー(空のタイトル、101文字のタイトル、1,001文字のメモ)
  - 削除の確認ダイアログでキャンセル → 残る、OK → 消える
- テスト用ユーザー2人で、他人のタスクへの PATCH と DELETE が 404 になることを確認する。
- テストで作ったユーザーとデータは最後に削除する。
