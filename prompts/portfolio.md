# ポートフォリオ化: README の作成と Public 化の準備

CLAUDE.md、docs/spec.md、Git の履歴(git log)、prompts/ の手順書を読んでから始めてください。
このリポジトリを Public にして、私のポートフォリオとして見せられるようにしたい。
作業は「1. 公開前の点検」→「2. README の作成」の順。Public への切り替えは私が GitHub の画面で行う。

## 1. 公開前の点検(先に報告して止まる)

次を、今のファイルだけでなく **Git の全履歴** も含めて調べ、結果を一覧で報告する。直す必要があるものは、直し方の案も出す。

- 秘密の値: Supabase のキー、DB のパスワード、接続文字列、トークンなど。
- 個人情報: 私や知り合いの本物のメールアドレス・名前。スクショ(screenshots/、references/)に写っていないか、画像も目で確かめる。
- コミットの作者情報: すべて noreply アドレスになっているか。
- 公開すると困る・恥ずかしいファイル: 試作の残り、大きすぎるファイル、意味のないファイルなど。
- Supabase のプロジェクトID など、公開しても問題はないが気になる人もいる情報があれば、それも知らせる(消すかどうかは私が決める)。

履歴を書き換える必要がある場合は、作業する前に必ず方法と影響を説明して確認をとる。

## 2. README.md の作成(点検の確認が済んでから)

### 読む人と目的
- 読む人: 採用担当や、一緒に働くかもしれない人。エンジニアとは限らない。
- 伝えたいこと: 私が「仕様を決め、AI(Claude Code)と分担して、本番で動くものを作り切った」こと。私の役割は PM / BA(要件定義・仕様・判断・受け入れ確認)。
- 言語: 日本語を主にし、冒頭に3〜4行の英語の要約を付ける。

### 構成(目安。より良い構成があれば提案してよい)
1. タイトルと一言の説明、本番の URL(https://todo-app-rho-steel-65.vercel.app)
2. 英語の要約(3〜4行)
3. スクショ: PC とスマホの主な画面(今日ビュー、詳細パネル、スマホの一覧)。screenshots/ から選ぶか、Playwright で撮り直して docs/images/ に置く。テスト用のきれいなデータで撮ること。
4. できること: Must 機能 F-01〜F-12 を短く。
5. 作り方の流れ(ここを一番丁寧に): 次の順で、それぞれ何をしたか・なぜそうしたかを短く書く。
   - 仕様書を先に作った(機能一覧、画面、ERD、API、業務ルール)。迷う点は「小さく作って後で広げやすい」を基準に決めた。
   - 動くプロトタイプで流れを確かめた。
   - デザインを作り、スキルで磨き、テーマ(ブルー/ピクセル/ピクセル貴族)を試した。
   - 7つのステップに分け、手順書(prompts/)と CLAUDE.md で AI に指示した。各ステップの終わりに止まって報告させ、私が確認してから次へ進めた。
   - 公開と運用まで行い、最後に仕様書を実装に合わせて更新した。
6. 私が判断したこと・こだわったこと(PM の視点): 例として
   - 確認メールなしでの自動ログイン(仕様と使いやすさを優先)
   - リストを消してもタスクは残す(事故を防ぐ)
   - 「今日」の判定は端末の日付で行う(時差によるずれを防ぐ)
   - テスト用ユーザーのルール(本物のデータに触らせない)
   - そのほか、履歴や手順書から読み取れる判断があれば足してよい。ただし私が実際に判断していないことは書かない。
7. つまずいたことと学んだこと: 例として
   - Prisma は管理者として DB につなぐため RLS が効かない → API の user_id での絞り込みを本当の守りにした
   - Supabase の直通接続は IPv6 のみ → IPv4 の共有プール経由に切り替えた
   - Vercel は GitHub につないだ後の push でないとデプロイが始まらなかった
8. 技術構成: Next.js 16 / React 19 / Prisma 7 / Supabase(Auth・PostgreSQL)/ Zod / Vercel(ソウル)。
   画面 → API → DB の流れと、守り(ログイン確認・user_id での絞り込み・RLS)を Mermaid の図で示す(GitHub 上で図として表示される)。
9. ドキュメント: docs/spec.md、CLAUDE.md、prompts/ へのリンクと、それぞれ何かの一言。
10. 手元で動かす方法: 必要なもの、.env.example の使い方、npm install / npm run dev。マイグレーションの手順は CLAUDE.md を参照と書く。

### 書き方
- 一文は短く、専門用語には一言の説明を付ける。
- 数字や事実は、仕様書・履歴・実際のアプリで確かめられるものだけ。盛らない。
- 新規登録は誰でもできる状態なので、「試す場合はテスト用のメールで登録できます」と一言入れるかどうかを提案する。
