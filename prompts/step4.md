このステップは「前半: 機能を作る」「後半: Vercel に公開する」の2つに分かれています。前半が終わったら一度止まってください。

## 前半: 機能を作る

### 対象の機能
- F-03 タスク追加: 一覧上部の入力欄にタイトルを入れて Enter。
- F-04 タスク一覧: 仕様書 第2章の初期の並び順(未完了が上 → 期限が近い順 → 優先度が高い順)で表示。
- F-05 完了 / 未完了に戻す: チェックを押すだけで切り替え。completed_at の記録と消去も仕様どおりに。

このステップでは、リスト分け・「今日」ビュー・絞り込み・編集・削除は作らない(ステップ5〜6で作る)。
一覧はひとまず「自分の全タスク」を表示すればよい。

### API
- 仕様書 第7章のうち、GET /api/tasks、POST /api/tasks、PATCH /api/tasks/:id(このステップでは status の切り替えのみ)を作る。
- すべての API で、src/lib/auth.ts を通してログイン中のユーザーを確かめ、そのユーザーの user_id で絞り込む。他人のタスクや存在しない ID には 404 を返す(CLAUDE.md の「データの持ち主チェック」)。
- 入力チェックは Zod(仕様書 第8章: タイトル必須・1〜100文字・前後の空白は削除)。画面とAPIで同じスキーマを使う。
- エラーの返し方は仕様書 第7章どおり(400 / 401 / 404、本文は { "error": "メッセージ" })。

### 画面
- /tasks を本物のタスク一覧(S-03)にする。見た目は references/design/html/pc-main.html と sp-list.html(と png/ の同名画像)に合わせる。
  - サイドバーやリスト名など、まだ機能がない部分は見た目だけ置くか、省いてよい。どうしたかを報告すること。
- タスクが0件のときは仕様書 第5章の「空のとき」の表示にする。
- 追加と完了の切り替えは、画面を先に変えてから保存する(仕様書 第9章の楽観的更新)。失敗したら元に戻してエラーを表示する。
- ログアウトはステップ3と同じように使えるようにしておく。

### 確認
- Playwright で PC(1280幅)とスマホ(390幅)の両方で次を試し、スクショを screenshots/step4/ に保存する。
  - 追加 → 一覧に出る → 完了 → 取り消し線と並び順の変化 → 未完了に戻す
  - 空のタイトルや101文字のタイトルで追加 → エラー表示
  - 0件のときの表示
- データの持ち主チェック: テスト用ユーザーを2人作り、A のタスクの ID で B が GET / PATCH すると 404 になることを確認する。
- テストで作ったユーザーとデータは最後に削除する。

## 後半: Vercel に公開する(私の「後半に進んで」の合図のあとで)

- GitHub に非公開(Private)リポジトリを作って push する。認証など私の操作が必要な所は、手順を示して待つ。
- Vercel にプロジェクトを作り、GitHub とつなぐ。
- 先に確認しておくこと:
  - src/generated/ は Git に入れていないので、Vercel のビルド中に Prisma Client が作られるようにする。
  - 環境変数は Vercel の画面に私が入力する。どの変数が本番で必要か(DIRECT_URL が必要かどうかも含めて)を示す。値はチャットに書かない。
  - Vercel のサーバー処理の場所(Function Region)を、Supabase の DB と同じソウル(icn1)に合わせる。
  - Supabase の Authentication → URL Configuration の Site URL など、本番の URL に合わせて変える必要がある設定があれば示す。
- 公開後、本番の URL で、スマホからログインとタスク追加ができることを確認する手順を示す。
